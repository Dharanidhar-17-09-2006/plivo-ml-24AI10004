LLM Speedrun Summary

Architecture & Parameters

  • Model Type: Small GPT (Decoder-only Transformer)
  • Parameter Count: 1,339,840 (~1.3M)
  • Tokenizer: Byte-level (Vocab: 256)
  • Context Length: 128 tokens
  • Optimization: AdamW + 100-step Warmup + Cosine Decay

Strategic Decisions

Why Byte-level? Hindi characters occupy 3 bytes in UTF-8. While BPE shortens sequences, it increases the embedding table size. In a 2,000-step "speedrun," the model doesn't have enough updates to learn a 384+ vocab effectively. Reverting to bytes ensured every parameter received frequent updates.

Why AdamW/Cosine? The baseline used a constant LR which left performance on the table. Implementing a decay allowed us to use a higher peak LR (6e-4) to learn quickly at the start while cooling down for better final loss.

AI vs. Human Breakdown

Machine Done: AI assistants were used to generate the AdamW optimization loop, the BPE training script logic, and the boilerplate for the LR scheduler.

Human Done: Analyzed the BPB regression in Run 3. Formulated the hypothesis that BPE's larger vocab was the bottleneck for a 2,000-step run. Decided to revert to the Byte tokenizer and focus on LR scheduling and gradient stability.
